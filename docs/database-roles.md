# Agent checkpoint database role contract

S8 base: `2ead2837cf0007d4fcb18a047c9a21ae1ad788b0`. Pinned SDK migrations are executed without editing or synthesizing history.

Run `psql -X -v ON_ERROR_STOP=1 -f docs/database-roles.sql` as the provisioning operator against a verified database. It creates NOLOGIN `map_agent_owner`, restricted NOINHERIT `map_agent_migrator` member of owner, and `map_agent_runtime`; only langgraph object ownership moves, preserving rows and other roles' ACLs. Set unique passwords through R7's secret channel. This SQL uses the existing default `LANGGRAPH_SCHEMA=langgraph`; any custom schema requires an independently reviewed corresponding provisioning script.

Run immutable Agent image entrypoint `python`, command `-m app.checkpoint_migrate`, with only `AGENT_CHECKPOINT_MIGRATION_DSN` (libpq DSN, map_agent_migrator) and optional LANGGRAPH_SCHEMA. No POSTGRES_PASSWORD, serving settings, Gemini/Hub/Redis/encryption keys are required. The module imports no application settings or providers. It sets the owner role and search_path, uses autocommit on one connection and a session advisory lock (concurrent-index migrations cannot run inside a transaction). Connect/lock timeout 10s, per-statement timeout 5m; launcher overall timeout 15m. Noncontiguous/future history is rejected before setup. Invalid indexes cause failure requiring operator recovery, with history and rows preserved. Reapply the SQL ACL list after migration.

Serving uses POSTGRES_USER=map_agent_runtime plus the unique POSTGRES_PASSWORD, host/port/database, LANGGRAPH_SCHEMA and existing checkpoint encryption secrets. Do not include AGENT_CHECKPOINT_MIGRATION_DSN. Startup performs SELECT-only validation of exact current SDK migration sequence, four tables and three valid/ready concurrent indexes, runtime identity/privileges/owner membership and schema owner. It never calls saver.setup or CREATE SCHEMA. Missing/stale/future/gapped versions, elevated role, invalid indexes or DB failure stop startup, before an unvalidated saver becomes available.

Runtime has schema USAGE; checkpoint_migrations SELECT; checkpoints/checkpoint_blobs/checkpoint_writes SELECT/INSERT/UPDATE/DELETE. No sequence or cross-service access. Future objects fail closed until reviewed grants. Preserve CHECKPOINT_ENC_KEYS and ACTIVE_KID including old kids; never rewrite ciphertext or claim old plaintext is reencrypted. Migration needs no encryption key.

R7 cutover: quiesce Agent jobs, record source/image/role/ACL/ciphertext fingerprints and backup; provision/migrate/grant; start candidate with runtime-only DB credential; require schema guard, encrypted put/get/list/write/delete and SQLSTATE42501 cross-schema/DDL checks. Recompare existing ciphertext and account for synthetic writes. No GCP changes are performed by R2. S8 Agent calls setup at startup and is incompatible with reduced runtime privileges, so image-only rollback to S8 is forbidden. Retain candidate and recover forward; use only a separately verified compatible image/config. No DB downgrade, history rewrite or old backup restoration over new writes.
